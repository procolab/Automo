FortiGate monitoring and automation, these are the most commonly used REST API endpoints along with example JSON responses.
Authentication (most common):
curl -k \
-H "Authorization: Bearer TOKEN" \
https://FORTIGATE/api/v2/monitor/system/status
FortiGate primarily uses token-based authentication with Authorization: Bearer <API_TOKEN>.

1. System Status
This endpoint returns hostname, model, serial number, firmware version, and build information.
### API
GET /api/v2/monitor/system/status

### cURL
curl -k \
-H "Authorization: Bearer TOKEN" \
https://FGT/api/v2/monitor/system/status

### Sample JSON
{
  "http_method": "GET",
  "results": {
    "hostname": "Office-FGT",
    "model": "FGT100F",
    "model_name": "FortiGate",
    "serial": "FGTXXXXXXXXXXXX",
    "version": "v7.4.8",
    "build": 2795
  },
  "status": "success"
}

1. Configuration Endpoints (/api/v2/cmdb/)
These endpoints map directly to FortiOS config commands. They accept GET to view configurations, POST to create objects, PUT to update, and DELETE to remove them.

1.1 Firewall Policies: /api/v2/cmdb/firewall/policy/
(Used to read, create, or update firewall rules)
1.2 Firewall Addresses: /api/v2/cmdb/firewall/address/
(Used to manage individual IP/FQDN network objects)
1.3 Address Groups: /api/v2/cmdb/firewall/addrgrp/
(Used to bundle address objects for policy assignment)
1.4 Services (Ports): /api/v2/cmdb/firewall/service/custom/
1.5 Virtual IPs (NAT): /api/v2/cmdb/firewall/vip/
1.6 Static Routing: /api/v2/cmdb/router/static/
1.7 System Global Settings: /api/v2/cmdb/system/global/
1.8 Network Interfaces: /api/v2/cmdb/system/interface/

2. Monitoring & State Endpoints (/api/v2/monitor/)
These endpoints are used to gather data on the current operational state of the firewall. They are almost exclusively accessed via GET requests.

2.1 System Resource Status: /api/v2/monitor/system/status/
(Returns CPU, memory, uptime, and firmware version details)
2.2 Interface Statistics: /api/v2/monitor/system/interface/
(Monitors live bandwidth traffic and status per port)
2.3 Firewall Sessions: /api/v2/monitor/firewall/session/
(Fetches the active stateful session table)
2.4 DHCP Leases: /api/v2/monitor/system/dhcp/
2.5 IPsec VPN Status: /api/v2/monitor/vpn/ipsec/
(Tracks tunnel status, up/down history, and bandwidth)
2.6 SSL-VPN Active Users: /api/v2/monitor/vpn/ssl/

Tips for Using the API
• Authentication: All requests must include an access token generated from a REST API Admin account, passed inside the headers as Authorization: Bearer <token>.
• VDOM Context: If Virtual Domains (VDOMs) are enabled, you must append ?vdom=<vdom_name> to your endpoint URI to ensure you are modifying or reading the correct domain.
• GUI API Preview: If you are running FortiOS 7.0 or newer, you can build a configuration change manually in the Web GUI, click the API Preview button, and copy the exact JSON payload and endpoint required to recreate that step in code.

For FortiGate Firewall Policy Management, the CMDB API endpoint is:

/api/v2/cmdb/firewall/policy


Operations:

Create Policy → POST
View Policy → GET
Update Policy → PUT
Delete Policy → DELETE
Move/Reorder Policy → ACTION=move

FortiGate supports CRUD operations through the CMDB REST API.

1. Create Policy
cURL
curl -k -X POST \
-H "Authorization: Bearer TOKEN" \
-H "Content-Type: application/json" \
https://FGT/api/v2/cmdb/firewall/policy \
-d '
{
  "name": "Allow-Web",
  "srcintf": [{"name":"port1"}],
  "dstintf": [{"name":"port2"}],
  "srcaddr": [{"name":"all"}],
  "dstaddr": [{"name":"all"}],
  "service": [{"name":"HTTP"},{"name":"HTTPS"}],
  "schedule":"always",
  "action":"accept",
  "nat":"enable",
  "status":"enable"
}'

Python
import requests

url = "https://FGT/api/v2/cmdb/firewall/policy"

headers = {
    "Authorization": "Bearer TOKEN",
    "Content-Type": "application/json"
}

payload = {
    "name": "Allow-Web",
    "srcintf": [{"name":"port1"}],
    "dstintf": [{"name":"port2"}],
    "srcaddr": [{"name":"all"}],
    "dstaddr": [{"name":"all"}],
    "service": [{"name":"HTTP"}],
    "schedule":"always",
    "action":"accept",
    "nat":"enable"
}

r = requests.post(
    url,
    headers=headers,
    json=payload,
    verify=False
)

print(r.json())

7. Move Policy (Priority Change)

Most important during policy management.

Move Policy 100 before Policy 50.

cURL
curl -k -X PUT \
-H "Authorization: Bearer TOKEN" \
"https://FGT/api/v2/cmdb/firewall/policy/100?action=move&before=50"


Move Policy 100 after Policy 50.

curl -k -X PUT \
-H "Authorization: Bearer TOKEN" \
"https://FGT/api/v2/cmdb/firewall/policy/100?action=move&after=50"

Python
url = ("https://FGT/api/v2/cmdb/firewall/policy/"
       "100?action=move&before=50")

r = requests.put(
    url,
    headers=headers,
    verify=False
)

print(r.status_code)

9. Bulk Policy Update

Example: Disable multiple policies.

policies = [100,101,102]

for pid in policies:

    requests.put(
        f"https://FGT/api/v2/cmdb/firewall/policy/{pid}",
        headers=headers,
        json={"status":"disable"},
        verify=False
    )

Typical Success Response
{
  "http_method": "POST",
  "revision": "abcd1234",
  "status": "success",
  "http_status": 200
}
